02 · Dual-Process Model

Subconscious vs Conscious Mind

Inspired by dual-process cognition theory, the agent has a fast subconscious motor layer running at 60fps and a slow deliberative conscious mind that awakens only when something demands attention.

⚡ Subconscious (Every Frame)
YUKA vehicle steering — wandering, path following, obstacle avoidance
Raycaster ground-snap keeps agent on floor regardless of physics
Procedural IK gait — leg placement, stride, idle sway
Social state machine — detects nearby agents, initiates wave/chat
Player proximity detection — greeting/cooldown state machine
Drive decay updates + zone effect application every delta
Spatial memory zone tracking (throttled to every 2s)
Stuck detection, repath, wall avoidance via safety target
🧠 Conscious Mind (Event-Driven LLM)
Trigger: DriveManager.getUrgentDrive() returns non-null — a drive has crossed its threshold
Context assembly: Position, nearby entity table, task state, all 8 drives, zone description, spatial memory, personality bio
Memory retrieval: Tag-matched episodic memories from MemoryStream surface relevant past events
LLM call: Groq llama-3.1-8b-instant with 14 function-calling tools, returns 1–3 tool calls
Optional: web_search tool executes a real internet search and feeds results back in a second completion round
Output: AgentTasks enqueued with priority 10, displacing lower-priority subconscious tasks
Memorize: Decision stored to MemoryStream with context tags for future retrieval
Rate limit: 5 requests / 60 seconds per agent. Cooldown per-drive prevents spam.

03 · Internal Motivation

Drive System — 8 Needs

Each drive is a 0–100 numeric value. The subconscious monitors all drives every frame. When a drive falls below its threshold and the cooldown has passed, the conscious mind (LLM) is awakened to satisfy it. Drives decay naturally, spike from environmental events, and are amplified by personality drive weights.

Tidiness
Spikes when floor items detected
🧹
⚡ threshold: 40 satisfy: +30 | cooldown: 15s
Drives pick_up / place_at behavior. Decays at 3×count per second when floor items are nearby. Recovers when environment is clean.
Curiosity
Decays 1.5/s while idle
🔍
⚡ threshold: 30 satisfy: +40 | cooldown: 30s
Triggers explore tool — agent navigates to least-recently-visited zone. Stronger in Spark (1.6× weight). Biased by SpatialMemory.getLeastVisitedZone().
Helpfulness
Spikes when player is <10m away
🤝
⚡ threshold: 50 satisfy: +50 | cooldown: 10s
When high (and player nearby), agent proactively says something. Also satisfied by completing player-assigned tasks. Decays slowly at 0.5/s without player.
Social
Decays 1.0/s without nearby agents
💬
⚡ threshold: 35 satisfy: +45 | cooldown: 20s
Recovers +2/s per nearby agent. Triggers collaborate or say tools. Stronger in Spark (1.4×). Weaker in Nova (0.6×). Also satisfied by the present tool at the Arena.
Energy
Depletes 0.8/s while moving
⚡
⚡ threshold: 30 satisfy: +50 | cooldown: 45s
Creates the work → rest → work rhythm. Triggers rest tool — agent navigates to Garden bench and enters SEATED state for 16s. Zone effects (Garden, Observatory) boost recovery.
Focus
Decays 0.5/s while idle
🎯
⚡ threshold: 25 satisfy: +35 | cooldown: 40s
Improves in Workshop zone (+1.5/s). Drops with interruptions. When high, agents prefer focused tasks over socializing. Stronger in Nova (1.4× weight), weaker in Spark (0.6×).
Wonder
Decays 1.2/s always
✨
⚡ threshold: 25 satisfy: +45 | cooldown: 35s
Decays continuously — always pulling agents toward beauty and discovery. Satisfied by contemplate tool near POIs. Strongest in Nova (1.6×). Observatory and Gallery provide passive restoration.
Belonging
Decays 0.3/s outside preferred zone
🏠
⚡ threshold: 20 satisfy: +40 | cooldown: 60s
Recovers +1.5/s while in personality's preferredZones. Creates gentle territorial attachment — agents naturally return home. Slowest decay; longest cooldown prevents spam.
Drive Update Formula (per frame)
// Each drive updated in DriveManager.update() every frame:
drive[key] = clamp(0, 100, drive[key] + rate × delta × personality.driveWeights[key])

// Zone effects applied separately via DriveManager.applyZoneEffects():
drive[key] += zoneEffect[key] × delta × personality.driveWeights[key]

// Urgency check — most urgent = lowest value below threshold:
getUrgentDrive() → { drive: 'energy', value: 28 }  // triggers LLM

06 · Memory Architecture

Three-Layer Memory System

Agents have three distinct memory systems operating at different timescales and granularities. Together they give each agent a continuous sense of place, history, and familiarity that persists across the session.

🗺️
Spatial Memory
SpatialMemory.ts
Per-agent zone visit history. Updated every 2 seconds. Informs explore decisions and LLM context. Resets on session reload.
Tracks per zone:firstVisited, lastVisited, totalDuration, visitCount
Social record:Agent IDs met in each zone
Discoveries:POI/item IDs first seen there
avgSatisfaction:EMA of drive improvement while in zone
LLM injection:toContextString() — compact zone history string
Used by:explore tool, belonging drive, EXPLORE task
📖
Memory Stream
MemoryStream.ts
Episodic event log. Each LLM decision and completed action is stored with tags. Tag-based retrieval surfaces relevant memories for the next LLM call.
Entry types:ACTION (decisions), OBSERVATION (perceptions)
Tags:entity:player, id:agent-02, script:startup_explore
Retrieval:Tag intersection match, limit 5, sorted by recency
Lifecycle:reset() on first agent startup per session
Shared:Singleton across all agents, filtered by agentId
LLM injection:Memory context section in agent prompt
📍
POI Registry
POIRegistry.ts
Novelty-tracked Points of Interest. Zones register landmarks, views, and exhibits. Agents are pulled toward high-novelty POIs when Wonder or Curiosity is low.
Categories:view, exhibit, landmark, social_spot, workspace
currentNovelty:0–1, drops 0.8 on visit, recovers via noveltyDecay
Scoring:novelty / (distance + 1) — novel AND nearby wins
Update rate:Novelty recovery runs every 30s (throttled)
lookTarget:World-space point agent faces during GAZING phase
description:Injected into LLM when agent is near the POI

08 · Task Execution

Task Queue State Machine

The AgentTaskQueue runs a priority-sorted task queue with a 9-state phase machine. Tasks can preempt each other by priority. Stuck detection and repath logic ensure navigation always terminates.

IDLE
No task. Subconscious wander
↓ enqueue(task)
NAVIGATING
Pathfinding to target. Stuck detection active.
↓ arrived at target
ACTION_START
0.5s pause. Executes pick_up / place_at / interact
SEATED
SIT / REST tasks. Timer-based. Energy recovery.
LEANING
LEAN task. 6s default. Surface attachment pose.
GAZING
LOOK_AT / CONTEMPLATE. Faces lookTarget. Wonder restore.
EMOTING
EMOTE gesture in-place. 2.5s. No navigation.
PRESENTING
At Arena podium. Speech fires via TTS. 8s default.
↓ timer expires / action complete
COMPLETED
Task done. Starts next in queue or returns to IDLE.
Stuck Detection Algorithm
Records positions in a sliding 2.5s window. If total displacement <1.0m over the window, agent is stuck. Triggers repath. After 5 failed retries, task is abandoned (COMPLETED). Repath interval: 8s maximum before forced retry.
Priority System
Priority 10 — LLM-generated conscious decisions
Priority 8 — Startup exploration to preferred zone
Priority 0 — Subconscious WANDER fallback

Higher-priority tasks immediately preempt current task, which is re-queued.

10 · Autonomy Model

Level of Control & Autonomy

The agent operates with layered autonomy. The subconscious has full motor control at all times. The conscious mind can override with tasks at priority 10. Players can inject commands. The world shapes behavior through zone effects.

77%
Autonomous Agency
Agent decides what to do based entirely on its internal drives, personality, and environmental perception. No human tells it when to rest, explore, or contemplate.
50%
Environmental Influence
Zone effects passively modify drive decay rates without the agent's explicit knowledge. The world itself acts as a non-intrusive behavior shaper — zones heal, inspire, and focus.
30%
Player Override
Players can proximity-trigger greetings, dispatch tasks, or follow commands. These inject tasks at priority 10, preempting subconscious behavior — but the agent returns to autonomy after completion.
What the Agent CANNOT Do
Cannot modify zone influence effects or world geometry
Cannot spawn new objects or modify the scene graph directly
Cannot communicate directly with other agents (only approach + say)
Cannot read other agents' internal drives or thoughts
Cannot fly or move in Y axis — strictly ground-plane navigation
Cannot persist memory across browser sessions (SpatialMemory in-memory only)
Cannot create new tools or expand its own action vocabulary at runtime
Cannot navigate outside world bounds (hard-clamped in useAgentBrain)
11 · Known Constraints

Limitations & Design Tradeoffs

Understanding these limitations is critical for extending the system. Each represents an architectural decision with rationale, not just a missing feature.

⏱️
Rate-Limited Consciousness
Max 5 LLM calls per 60 seconds per agent. With 2 agents that's 10 req/min. The agent may not respond immediately to fast-changing situations. Cooldown per-drive (10–60s) adds further delays. Groq key rotation handles quota errors.
🧭
2D Pathfinding Only
Navigation uses AgentBrainClient which operates on a flat XZ navmesh. Stairs, ramps, and multi-floor buildings are not navigable. Y is always forced to floor Y=4.0 via downward raycasting. Vertical movement is structurally absent.
💾
No Cross-Session Memory
SpatialMemory and MemoryStream reset on page reload. Agents start fresh every session — no persistent personality evolution, learned preferences, or long-term relationship building. Each session is episodically independent.
🔮
No Inter-Agent Communication Protocol
Agents cannot exchange structured data or coordinate plans. Collaboration is physically proximate but cognitively individual — two agents near each other are not aware of each other's decisions unless they read the entity table's Status field.
🌐
LLM Hallucination Risk
At temperature 0.3 with tool_choice:auto, the LLM may generate invalid entity IDs or out-of-bounds coordinates. World bounds clamping catches coordinate issues. Invalid IDs are safely ignored by the registry lookup (returns null → task skipped).
👤
Single Agent Body Type
All agents use the same procedural robot mesh. Only LED accent color and scale differentiate them visually. There is no support for different body shapes, animation rigs, or non-bipedal locomotion without significant changes to useProceduralGait.
🎯
Implicit Interaction Range
Agents perceive entities based on whatever is injected into nearbyEntities from useAgentBrain — there's no explicit perception radius control in the tool schema. The LLM trusts the distance values in the entity table are accurate.
🔧
Tool Latency Coupling
The web_search tool requires a second Groq completion round (~2× latency). If the LLM decides to search, total response time doubles. This is transparent but can cause noticeable delays in agent speech or task generation.
12 · Building On This World

Developer Guide — Adding to the World

This section is a practical guide for a new developer who wants to add functional objects, environments, zones, or agents to The Ring. Each step includes the exact code patterns to use.

Register a New Zone
Any React component that renders a physical zone should register itself with ZoneInfluenceSystem on mount. The agent will automatically detect it, apply drive effects, and inject the description into LLM context. Add its center to parkRoutines.ts to make it navigable.
Register zone in your zone component (useEffect) src/components/world/zones/YourZone.tsx 
import { ZoneInfluenceSystem } from "@/components/systems/ZoneInfluenceSystem";
import * as THREE from "three";

// Inside your React zone component:
useEffect(() => {
  ZoneInfluenceSystem.register({
    zoneId: "lab",
    zoneName: "Research Lab",
    center: new THREE.Vector3(25, 4, 30),
    radius: 22,
    effects: {
      focus: 2.5,      // +2.5 focus/s while inside
      curiosity: 1.0,  // +1.0 curiosity/s
      energy: -0.4,   // -0.4 energy/s (demanding)
    },
    moodLabel: "charged with discovery",
    environmentDescription: "Whiteboards cover the walls, filled with equations. The hum of equipment fills the air.",
  });

  return () => ZoneInfluenceSystem.unregister("lab");
}, []);

// Add to parkRoutines.ts for navigation:
ZONE_CENTERS["lab"] = new THREE.Vector3(25, 4, 30);
ALL_ZONE_IDS.push("lab");
Register a Point of Interest (POI)
POIs are specific landmarks, exhibits, or viewpoints agents will autonomously navigate to and contemplate when their Wonder or Curiosity drive is low. They carry a lookTarget (where the agent faces) and a description injected into LLM context when nearby.
Register a POI — automatic novelty decay on visit src/components/world/zones/YourZone.tsx 
import { POIRegistry } from "@/components/systems/POIRegistry";

useEffect(() => {
  POIRegistry.getInstance().register({
    id: "lab-hologram",
    name: "DNA Hologram Display",
    position: new THREE.Vector3(25, 4, 28),
    lookTarget: new THREE.Vector3(25, 6, 25),  // face up toward the hologram
    description: "A shimmering holographic DNA strand rotates slowly, casting blue light on the walls.",
    zoneId: "lab",
    category: "exhibit",
    noveltyDecay: 0.15,  // fully novel again after ~7 minutes
    currentNovelty: 1.0,
  });

  return () => POIRegistry.getInstance().unregister("lab-hologram");
}, []);
Add an Interactable Object
Objects agents can pick_up, place_at, or interact with must be registered with InteractableRegistry. The registry manages ownership (claimed/unclaimed), world positions, and place areas. The LLM sees these in the entity table and can act on them.
Register pickable + placeable object src/components/world/YourComponent.tsx 
import { InteractableRegistry } from "@/components/systems/InteractableRegistry";

useEffect(() => {
  const reg = InteractableRegistry.getInstance();

  // Register the item (pickable from floor)
  reg.registerItem({
    id: "crystal-sample-1",
    name: "Crystal Sample",
    objectType: "crystal",
    worldPosition: new THREE.Vector3(26, 4, 32),
    isOnFloor: true,     // shows as (A) available in entity table
    homeAreaId: "lab-shelf-1",
  });

  // Register a surface area (agents can place items here)
  reg.registerArea({
    id: "lab-shelf-1",
    zoneId: "lab",
    worldPosition: new THREE.Vector3(28, 5.5, 30),
    isEmpty: true,       // shows as (E) empty — valid placement target
  });

  return () => {
    reg.unregisterItem("crystal-sample-1");
    reg.unregisterArea("lab-shelf-1");
  };
}, []);

Add a New Drive
Adding a drive requires extending AgentDrives, DRIVE_CONFIGS, DriveManager.update(), and ensuring the LLM decision guidance section mentions what to do when it's LOW. The drive system is fully data-driven — you only need to add the logic once.
Minimal new drive — Creativity src/lib/agent-drives.ts 
// 1. Extend interface:
export interface AgentDrives {
  // ... existing drives ...
  creativity: number;  // Satisfied by interact with art exhibits
}

// 2. Add config:
DRIVE_CONFIGS.creativity = {
  threshold: 30, decayRate: 0.8,
  satisfyAmount: 50, cooldownSec: 25,
  label: "Creativity"
};

// 3. Initialize in DriveManager constructor:
this.drives.creativity = 70;
